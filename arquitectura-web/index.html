Prevalidacion de COES

Se incorpora una conexion automatica para descargar las liquidaciones mensuales de COES (VTEA y VTP) y contrastar los montos de cada factura antes de la derivacion, sin intervencion manual.

1

Deteccion del tipo de cargo

El concepto extraido del XML se analiza para identificar si es un Peaje o una transferencia COES (Potencia = VTP, Energia = VTEA).

2

Descarga automatica mensual

Un proceso diario descarga los excels oficiales de COES para el mes vigente. Si COES aun no publico el mes actual, se usa el ultimo periodo ya disponible o se retrocede mes a mes hasta encontrar el mas reciente.

3

Indexacion por codigo de informe

Cada excel se identifica por su codigo de informe COES (ej. COES/D/DO/SME-INF-090-2026), el mismo que aparece en el concepto de la factura, para ubicar el archivo exacto del mes correspondiente.

4

Cruce de montos por RUC

El sistema reconstruye la matriz completa de pagos (las planillas de COES vienen partidas en varios bloques apilados para impresion) y ubica el cruce entre el RUC de Alupar (La Virgen) y el RUC del proveedor, en cualquiera de los dos sentidos: Alupar emite la factura (cobra) o a Alupar le facturan (paga).

5

Resultado sin bloquear el flujo

El resultado (validado, no coincide, no encontrado) queda visible en una columna del tablero; nunca detiene el procesamiento del documento, solo lo marca para revision si hace falta.

Vista dedicada COES

Pagina propia del panel con resumen horizontal de las contrapartes de Alupar (nombre, RUC, monto) agrupadas segun si Alupar cobra o paga, mas un grafico de barras comparativo por empresa.

Verificador manual

Permite elegir dataset (VTEA/VTP) y periodo, ingresar un RUC y un monto, y validar el cruce a mano contra la matriz oficial de COES sin depender del flujo automatico.

Multiples bloques, una sola tabla

Las planillas de COES dividen una tabla unica en varios tramos apilados para que entre en una pagina impresa; el sistema los reconstruye automaticamente en una sola matriz antes de validar.

Carga masiva desde ZIP

Cada carpeta del ZIP se interpreta como un registro independiente y puede incluir XML, PDF y ZIP anidados.

ZIP maestro

El usuario selecciona un solo archivo ZIP desde la interfaz y el sistema lo procesa completo.

Carpeta = registro

Cada carpeta interna genera un registro nuevo con su propio conjunto de archivos y metadatos.

Archivos soportados

Se aceptan XML, PDF y ZIP, manteniendo la misma lógica de ingestión que el flujo normal.

Procesamiento iterativo

El backend expande el ZIP, agrupa por carpeta y llama al endpoint de intake para cada grupo.

Visualizacion de correos

La plataforma puede mostrar el cuerpo del correo como una ventana desplegable, útil para revisar el contexto original.

Metadatos del mensaje

La plataforma muestra información clave del correo, como remitente, destinatario y fecha de recepción.

Vista previa segura

El correo se podrá visualizar desde la plataforma como vista previa.

Uso operativo

Permite validar el correo original sin salir del tablero ni perder trazabilidad del documento.
